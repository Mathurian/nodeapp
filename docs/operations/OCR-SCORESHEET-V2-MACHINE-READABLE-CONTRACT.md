# Scoresheet V2 Machine-Readable Contract

## Purpose

`TASK-34.27` defines the smallest paper-format change needed to improve scoresheet import assurance without changing the scoring workflow.

The v2 goal is not a visual redesign. It is a constrained OMR target:

- keep the sheet human-readable for judges
- keep the same category criteria and score values
- add enough machine-readable structure to eliminate fragile handwritten-mark inference
- keep v1/current sheets supported only through review-required or manual fallback routing

## Scope

This contract applies to future machine-readable scoresheets generated by the application. It does not change the runtime import path by itself.

In scope:

- registration anchors
- a fixed template/version identity
- page identity fields
- score mark regions designed for OMR
- v1/v2 routing rules
- extraction metadata required for assurance decisions
- operator print, fill, and scan guidance

Out of scope:

- changing category criteria, score caps, or score values
- changing judge, delegate, certification, or manual-entry behavior
- importing handwritten comments
- auto-submit or auto-certification before v2 calibration proves an assurance band
- phone-photo support as the first v2 target

## Format Identity

The first v2 template family should use a new template identity instead of modifying the current v1 Education key in place.

Recommended naming:

- family: `education`
- version: `v2`
- initial key: `education_omr_v2`
- human label: `Education OMR v2`

The generated page must include:

- human-readable text: `SCORESHEET-V2`
- human-readable template key, for example `education_omr_v2`
- a fixed machine-readable version strip in a known header location
- a short page identity code printed as text for operator troubleshooting

The version strip should be simple filled/unfilled boxes, not OCR text. A later implementation can add QR if useful, but QR is not required for the first v2 extractor.

## Registration Anchors

V2 pages must include four high-contrast registration anchors:

- top-left
- top-right
- bottom-left
- bottom-right

Anchor requirements:

- black filled squares
- placed inside the printable area, not at the physical paper edge
- surrounded by a white quiet zone
- identical size on every generated sheet
- not reused as score marks or decoration

Recommended starting geometry for letter portrait output:

- page size: `8.5in x 11in`
- anchor size: `0.18in` to `0.24in`
- anchor inset from page edge: `0.30in`
- quiet zone: at least `0.08in`

The v2 extractor should use these anchors to estimate page orientation, scale, skew, and crop. If any anchor is missing, merged with writing, or outside expected tolerance, the upload should be rejected rather than guessed.

## Page Identity

The upload context remains authoritative. The sheet should not be required to carry all database identity in machine-readable form.

The generated sheet should print these human-readable fields:

- event name
- contest name
- category name
- contestant number/name
- judge number/name
- generated timestamp or packet id

For machine checks, the page should include a short identity code with bounded length:

- `tenant/event/contest/category` packet code
- contestant sequence code
- judge sequence code
- page sequence, normally `1/1`
- template key/version

The code can be printed as text and optionally encoded as a binary mark strip in later tasks. In v2 import, this identity should be used as a mismatch warning or rejection input, not as the sole source of scoring context. The user still uploads from, or confirms, the current category, contestant, and acting judge context.

## Score Mark Regions

V2 must replace freeform score-grid marks with explicit mark regions.

For each criterion row:

- print the criterion label in the existing human-readable row area
- print one mark target for each score value
- keep the existing score values, starting with the category/template values currently used by v1 Education: `6, 5, 4, 3, 2, 1, 0`
- require exactly one filled mark per criterion row

Recommended mark design:

- circular bubbles or square check boxes are acceptable
- bubble/box outer size: approximately `0.16in` to `0.22in`
- inner fill area should be large enough for ordinary pen or marker fill
- minimum quiet zone around each mark target: `0.04in`
- avoid heavy grid lines through or touching mark targets
- use thin light row guides rather than dark grid lines around the marks

The first v2 implementation should prefer filled bubbles/boxes over checkmarks. Filled regions produce a simpler binary signal and reduce false high-confidence wrong marks.

## Row Layout

The sheet must keep a deterministic row order that maps to the template definition.

For Education v2, row order should remain:

1. Knowledge
2. Technique
3. Safety
4. Attitude
5. Personality Projection
6. Volume
7. Audience Engagement
8. Appropriate Attire
9. Preparation
10. Time Management

The extractor should derive criterion mapping from the v2 template definition after alignment, not from OCR of row labels.

## Mark Resolution Rules

The v2 extractor should classify each row conservatively.

Accepted row:

- exactly one mark target is filled above the calibrated fill threshold
- every other target in the row is below the conflict threshold
- the winning mark has enough margin over the next-highest mark
- the row is inside an anchor-aligned page transform with acceptable residual error

Rejected row:

- no mark target is filled
- more than one target is filled
- the winning mark is too close to another mark
- the row is damaged, cropped, obscured, or outside transform tolerance

Rejected rows must not become high-confidence scores.

## V1 And V2 Routing

The import pipeline must route sheets before extraction:

- v2 route: anchors and version strip are detected within tolerance
- v1/current route: no valid v2 anchors/version strip; use existing current-sheet extractor and review-required gates
- unsupported route: neither v2 nor a supported v1 template can be recognized

Routing requirements:

- v2 confidence must not be inferred from text OCR alone
- v1/current sheets must not receive v2 assurance bands
- v2 sheets with missing anchors or a bad version strip should be rejected or routed to manual entry, not processed as v1
- current/v1 sheets remain review-required unless a separate future policy says otherwise

## Extraction Payload Additions

Future v2 extraction payloads should include these fields, either under the existing extraction JSON or a versioned subobject:

- `sheetVersion`: `v2`
- `templateKey`: for example `education_omr_v2`
- `templateVersion`
- `routingDecision`: `v2_omr`, `v1_review_required`, `unsupported`, or `rejected`
- `anchorQuality`
- `anchorResidualPx`
- `orientationCorrected`
- `versionStripMatched`
- `identityCode`
- `identityWarnings`
- `rowMarkMetrics`
- `rejectedRows`
- `multiMarkRows`
- `blankRows`
- `lowMarginRows`
- `falsePositiveGuardInputs`
- `qualityGate`
- `reviewBurdenMetrics`

Per row, `rowMarkMetrics` should include:

- criterion id/name
- score values and mark target positions
- fill ratios per target
- selected score, when accepted
- confidence margin
- row decision: `accepted`, `blank`, `multi_mark`, `low_margin`, or `damaged`

## Operator Guidance

Printing:

- print from the application-generated v2 PDF
- use letter portrait without scaling when possible
- avoid photocopying already-filled sheets
- do not crop margins or cover the anchors

Filling:

- fill exactly one bubble/box per criterion
- use dark blue or black pen/marker
- fill the target, not just a light checkmark
- if a row is corrected on paper, clearly void the bad mark and manually enter the score instead of relying on import

Scanning:

- scanner PDF is the first supported capture type
- use full-page scans
- avoid shadows, folds, glare, and heavy compression
- keep the whole page including all four anchors visible

Phone photos:

- not part of the initial v2 assurance target
- should remain disabled or review-required until real phone-photo calibration exists

## Assurance Policy

V2 exists to make assurance possible, not automatic.

Initial policy:

- v2 imports remain review-required until calibration proves a stronger band
- auto-submit and auto-certification remain disabled by default
- any row rejection, multi-mark row, blank row, or low-margin row blocks auto-submit
- any anchor or version-strip failure rejects the upload

Calibration must prove, at minimum:

- exact row match rate
- exact sheet match rate
- rejected row rate
- false high-confidence mark count
- false accepted-row count
- upload rejection rate
- runtime
- review burden compared with same-user manual entry

No v2 assurance band may be enabled based on raw extractor confidence alone.
